# Popover

Display floating content and contextual information with terminal-inspired popover components featuring animated transitions.

## Overview

The Popover component is a floating overlay element designed to display contextual content, tooltips, menus, or additional information when triggered by user interaction. Built on Radix UI's accessible popover primitive, it features a distinctive terminal aesthetic with bold 2px borders, monospace typography, and smooth fade animations that evoke the feel of context menus from retro computing interfaces.

## Features

- **Flexible Positioning**: Supports all 12 placement positions (top, bottom, left, right with start/center/end alignment)
- **Terminal-Inspired Design**: Bold 2px borders, monospace font, and sharp corners for retro computing aesthetic
- **Smooth Animations**: Fade-in/out transitions with transform-origin-aware animation origins
- **Portal Rendering**: Content renders in a portal to avoid z-index and overflow issues
- **Customizable Offset**: Configurable distance between trigger and popover content
- **Anchor Support**: Optional anchor element for advanced positioning scenarios
- **Fully Accessible**: Built on Radix UI with proper ARIA attributes, focus management, and keyboard navigation
- **TypeScript Support**: Fully typed with comprehensive prop definitions

## Installation

## API Reference

### Popover Props

The root Popover component from Radix UI:

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `open` | `boolean` | `undefined` | Controlled open state |
| `defaultOpen` | `boolean` | `false` | Default open state for uncontrolled usage |
| `onOpenChange` | `(open: boolean) => void` | `undefined` | Callback when open state changes |
| `modal` | `boolean` | `false` | Whether the popover is modal |

### PopoverTrigger Props

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `asChild` | `boolean` | `false` | Render as child element using Slot |
| ...rest | `PopoverPrimitive.Trigger` props | - | All Radix popover trigger props |

### PopoverContent Props

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `align` | `"start" \| "center" \| "end"` | `"center"` | Horizontal alignment relative to trigger |
| `side` | `"top" \| "bottom" \| "left" \| "right"` | `"bottom"` | Which side of the trigger to position on |
| `sideOffset` | `number` | `4` | Distance in pixels from the trigger |
| `alignOffset` | `number` | `0` | Offset from the aligned edge |
| `avoidCollisions` | `boolean` | `true` | Whether to flip when hitting viewport edges |
| `collisionPadding` | `number \| Padding` | `0` | Padding from viewport edges |
| `className` | `string` | `undefined` | Additional CSS classes to apply |
| ...rest | `PopoverPrimitive.Content` props | - | All Radix popover content props |

### PopoverAnchor Props

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| ...rest | `PopoverPrimitive.Anchor` props | - | All Radix popover anchor props |

### Type Definitions

```typescript
import * as PopoverPrimitive from "@radix-ui/react-popover";

// Root component

export { Popover, PopoverTrigger, PopoverContent, PopoverAnchor };
```

## Accessibility

### Keyboard Navigation

- **Tab**: Move focus to/within the popover
- **Shift + Tab**: Move focus backwards
- **Escape**: Close the popover
- **Enter/Space**: Open popover (when trigger is focused)

### Focus Management

The popover automatically:
- Focuses the first focusable element when opened
- Returns focus to the trigger when closed
- Traps focus within the popover when `modal={true}`

### ARIA Attributes

```tsx
{/* The popover automatically provides proper ARIA attributes */}
<Popover>
  <PopoverTrigger
    aria-haspopup="dialog"
    aria-expanded="false"
    aria-controls="popover-content"
  >
    Open
  </PopoverTrigger>
  <PopoverContent
    role="dialog"
    aria-labelledby="popover-title"
  >
    <h3 id="popover-title">Popover Title</h3>
    <p>Content here</p>
  </PopoverContent>
</Popover>

{/* For menu-style popovers */}
<PopoverContent role="menu" aria-label="Actions menu">
  <button role="menuitem">Edit</button>
  <button role="menuitem">Delete</button>
</PopoverContent>
```

### Screen Reader Support

- Trigger announces expanded/collapsed state
- Content is read when popover opens
- Use descriptive labels for trigger buttons
- Consider adding `aria-describedby` for complex content

```tsx

<Popover>

    @username
  </PopoverTrigger>

  </PopoverContent>
```

## Best Practices

### When to Use Popovers

✅ **Good Use Cases:**
- User profile cards and quick info
- Color pickers and selectors
- Quick action menus
- Form inputs for supplementary data
- Help tooltips with rich content
- Share or export options
- Filter and sort controls

❌ **Avoid Using Popovers For:**
- Critical confirmations (use Dialog instead)
- Long-form content (use Modal or Page)
- Navigation menus (use DropdownMenu)
- Simple tooltips (use Tooltip component)
- Content that needs to persist (use inline content)
- Mobile primary interactions (consider sheets/drawers)

### Design Guidelines

1. **Keep content concise**: Popovers should contain focused, scannable content
2. **Use consistent positioning**: Establish patterns for popover placement in your app
3. **Provide visual hierarchy**: Use headers, separators, and spacing for clarity
4. **Consider trigger context**: Position popovers where they won't obscure related content
5. **Include close mechanisms**: Clicking outside or pressing Escape should close the popover
6. **Mind the width**: Default 18rem (288px) works for most cases, adjust as needed
7. **Handle overflow**: Use `overflow-y-auto` for content that might exceed viewport

## Design Details

### Terminal Aesthetic Breakdown

The popover's terminal aesthetic is achieved through:

**Border and Background:**
- 2px solid border using `--border` color
- Background uses `--background1` for slight contrast
- Sharp corners (0px border-radius) for retro look
- Monospace font throughout (`font-mono`)

**Animation System:**
```css
/* Open animation */
data-[state=open]:animate-in
data-[state=open]:fade-in-0

/* Close animation */
data-[state=closed]:animate-out
data-[state=closed]:fade-out-0

/* Transform origin follows placement */
transform-origin: var(--radix-popover-content-transform-origin)
```

**Z-Index Layering:**
- Popover content: `z-50` (above most page content)
- Renders in portal to escape stacking contexts

## Performance

The Popover component is optimized for performance:
- Portal rendering avoids layout recalculations
- Lazy mounting - content only renders when open
- Minimal JavaScript footprint (~3KB including Radix)
- CSS-based animations with hardware acceleration
- Server-side rendering compatible
- Collision detection is efficient and batched

## Troubleshooting

### Popover not appearing

Ensure the trigger has proper event handling:

```tsx
{/* Make sure to use asChild with a valid interactive element */}
<PopoverTrigger asChild>
  <Button>Open</Button>
</PopoverTrigger>

{/* Or without asChild for a simple button */}
<PopoverTrigger>Open</PopoverTrigger>
```

### Popover appears in wrong position

Check for parent elements with `transform` or `overflow: hidden`:

```tsx
{/* Popover uses a portal, but transform parents can affect positioning */}
<div className="transform translate-x-0">
  <Popover>
    {/* Content renders in portal outside this container */}
  </Popover>
</div>
```

### Content cut off by viewport

Enable collision avoidance (default) and add padding:

```tsx
<PopoverContent
  avoidCollisions={true}
  collisionPadding={16}
>
  Content will flip to stay in viewport
</PopoverContent>
```

### Z-index conflicts

The popover uses `z-50` by default. Adjust if needed:

```tsx
<PopoverContent className="z-[100]">
  Higher z-index content
</PopoverContent>
```
