# Tabs

Organize content into switchable panels with terminal-inspired tab interfaces featuring buffer-style navigation and clean visual states.

## Overview

The Tabs component provides a navigational interface for organizing related content into discrete, switchable panels. Built with Radix UI primitives and a terminal aesthetic, it features multiple visual styles including the distinctive "buffer" variant that mimics terminal buffer tabs. The component uses monospace typography and clean borders that integrate seamlessly with the TermCN design system.

## Features

- **2 Visual Variants**: Default underline style and buffer-style tabbed interface
- **Terminal-Inspired Design**: Monospace typography with clean borders and subtle backgrounds
- **Keyboard Navigation**: Full keyboard accessibility with arrow key navigation
- **Buffer Tab Style**: Mimics terminal/editor buffer tabs with bordered segments
- **Flexible Content**: Each panel can contain any React content
- **Accessible by Default**: Built on Radix UI with proper ARIA attributes
- **TypeScript Support**: Fully typed with comprehensive prop definitions
- **Compound Component Pattern**: Composable API with Tabs, TabsList, TabsTrigger, and TabsContent

## Installation

```bash
npx termcn add tabs
```

This will install the Tabs component and its dependencies into your project.

- `@radix-ui/react-tabs` - Accessible tabs primitive

### Controlled State

Use controlled state for programmatic tab switching:

```tsx
import { useState } from "react";
import { Tabs, TabsList, TabsTrigger, TabsContent } from "@/components/ui/tabs";

export default function ControlledTabs() {
  const [activeTab, setActiveTab] = useState("tab1");

  return (
    <div>
      <button onClick={() => setActiveTab("tab2")}>Go to Tab 2</button>
      <Tabs value={activeTab} onValueChange={setActiveTab}>
        <TabsList>
          <TabsTrigger value="tab1">Tab 1</TabsTrigger>
          <TabsTrigger value="tab2">Tab 2</TabsTrigger>
        </TabsList>
        <TabsContent value="tab1">Content 1</TabsContent>
        <TabsContent value="tab2">Content 2</TabsContent>
      </Tabs>
    </div>
  );
}
```

## API Reference

### Tabs Props

The root container component that manages tab state.

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `defaultValue` | `string` | - | The value of the tab to select by default (uncontrolled) |
| `value` | `string` | - | The controlled value of the active tab |
| `onValueChange` | `(value: string) => void` | - | Callback when the active tab changes |
| `orientation` | `"horizontal" \| "vertical"` | `"horizontal"` | The orientation of the tabs |
| `dir` | `"ltr" \| "rtl"` | - | Reading direction |
| `activationMode` | `"automatic" \| "manual"` | `"automatic"` | Whether tabs activate on focus or require explicit selection |
| `className` | `string` | - | Additional CSS classes |

### TabsList Props

The container for tab triggers.

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `variant` | `"default" \| "boxed"` | `"default"` | The visual style of the tab list |
| `className` | `string` | - | Additional CSS classes |
| `loop` | `boolean` | `true` | Whether keyboard navigation loops |

### TabsTrigger Props

The individual tab button.

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `value` | `string` | - | **Required.** Unique value identifying this tab |
| `variant` | `"default" \| "buffer"` | `"default"` | The visual style of the trigger |
| `disabled` | `boolean` | `false` | Whether the tab is disabled |
| `className` | `string` | - | Additional CSS classes |

### TabsContent Props

The content panel for each tab.

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `value` | `string` | - | **Required.** Must match a TabsTrigger value |
| `forceMount` | `boolean` | `false` | Force mount content even when inactive |
| `className` | `string` | - | Additional CSS classes |

## Best Practices

### When to Use Tabs

✅ **Good Use Cases:**
- Organizing related content into logical sections
- Settings or configuration panels
- Code editor file buffers
- Documentation with multiple sections
- Dashboard views with different data displays
- Step-by-step workflows (though consider Stepper for linear processes)

❌ **Avoid Using Tabs For:**
- Navigation between unrelated pages (use proper navigation)
- Content that should all be visible at once (use sections)
- Very few options with little content (use radio buttons or toggles)
- Mobile-first designs with many tabs (consider accordion or dropdown)
- Critical information that users might miss by not switching tabs

### Design Guidelines

1. **Keep tab labels short**: 1-3 words maximum for readability
2. **Logical ordering**: Place most important/frequently used tabs first
3. **Consistent content depth**: Each tab should have similar amounts of content
4. **Indicate current state**: Use the default styling to show active state
5. **Consider mobile**: Ensure tabs work well on smaller screens
6. **Use meaningful labels**: Tab names should clearly describe content

## Design Details

### Default Variant Implementation

The default variant uses an underline approach with blue accent:

- Inactive: `text-muted-foreground` with transparent bottom border
- Active: `text-ansi-blue` with 2px blue bottom border
- Base styling includes monospace font and consistent padding

```css
/* Default trigger styling */
.trigger {
  border-bottom: 2px solid transparent;
  color: var(--muted-foreground);
}
.trigger[data-state="active"] {
  color: var(--ansi-blue);
  border-bottom-color: var(--ansi-blue);
}
```

### Buffer Variant Implementation

The buffer variant mimics terminal/editor buffer tabs:

- Uses right border separators instead of bottom underline
- Active state has elevated background (`background2`)
- No bottom border for a cleaner segmented look

```css
/* Buffer trigger styling */
.trigger-buffer {
  border-right: 1px solid var(--border);
  border-bottom: none;
}
.trigger-buffer:last-child {
  border-right: none;
}
.trigger-buffer[data-state="active"] {
  background: var(--background2);
  color: var(--foreground);
}
```

## Performance

The Tabs component is optimized for performance:

- **Lazy rendering**: Inactive tab content is not rendered by default
- **Minimal re-renders**: Only the active panel re-renders on switch
- **CSS-only styling**: No JavaScript required for visual states
- **Small bundle size**: ~3KB including Radix UI primitive
- **SSR compatible**: Works with server-side rendering
- **Tree-shakable**: Import only what you need

## Troubleshooting

### Tab content not showing

Ensure the `value` prop on `TabsTrigger` matches the `value` on `TabsContent`:

```tsx
{/* ✅ Correct - values match */}
<TabsTrigger value="tab1">Tab 1</TabsTrigger>
<TabsContent value="tab1">Content</TabsContent>

{/* ❌ Wrong - values don't match */}
<TabsTrigger value="tab1">Tab 1</TabsTrigger>
<TabsContent value="tab-1">Content</TabsContent>
```

### Keyboard navigation not working

Ensure tabs have proper focus management:

```tsx
{/* Ensure TabsList and TabsTriggers are direct children */}
<Tabs>
  <TabsList>
    <TabsTrigger value="1">Tab 1</TabsTrigger>
    <TabsTrigger value="2">Tab 2</TabsTrigger>
  </TabsList>
  {/* ... */}
</Tabs>
```

### Styling conflicts with custom classes

Use the `cn()` utility for proper class merging:

```tsx
import { cn } from "@/lib/utils";

<TabsTrigger
  className={cn("custom-class", conditionalClass && "another-class")}
  value="tab1"
>
  Tab 1
</TabsTrigger>
```

### Variants not applying correctly

Ensure both `TabsList` and `TabsTrigger` use matching variants:

```tsx
{/* For buffer style, both need the variant */}
<TabsList variant="boxed">
  <TabsTrigger variant="buffer" value="1">Tab 1</TabsTrigger>
  <TabsTrigger variant="buffer" value="2">Tab 2</TabsTrigger>
</TabsList>
```

```diff
  import { Tabs, TabsList, TabsTrigger, TabsContent } from "@/components/ui/tabs";

  // Monospace font and theme colors apply by default
```
