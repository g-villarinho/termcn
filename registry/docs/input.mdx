# Input

Capture user input with terminal-inspired text fields featuring minimal aesthetics and versatile variants.

## Overview

The Input component is a foundational form element designed to capture text input from users. Built with a terminal aesthetic in mind, it features a clean, borderless design by default with optional bordered variants, monospace typography, and seamless integration with the TermCN theme system. The component supports multiple sizes and maintains the distinctive terminal feel throughout all states.

## Features

- **2 Visual Variants**: Default (minimal) and Bordered for different design contexts
- **3 Size Options**: Small, Default, and Large for flexible layouts
- **Terminal Typography**: JetBrains Mono font for authentic terminal aesthetics
- **Clean Transitions**: Smooth color transitions on focus and interaction
- **Native File Input Support**: Styled file input with transparent background
- **Selection Styling**: Custom selection colors using primary theme colors
- **Fully Accessible**: Proper focus states, disabled handling, and semantic HTML
- **TypeScript Support**: Fully typed with comprehensive prop definitions

## Installation

```bash
npx termcn add input
```

This will install the Input component and its dependencies into your project.

## API Reference

### Input Props

The Input component extends `React.ComponentProps<"input">` (excluding `size`) and accepts the following props:

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `variant` | `"default" \| "bordered"` | `"default"` | The visual style variant |
| `inputSize` | `"sm" \| "default" \| "lg"` | `"default"` | The size of the input |
| `type` | `string` | `"text"` | The HTML input type |
| `className` | `string` | `undefined` | Additional CSS classes to apply |
| `disabled` | `boolean` | `false` | Disable the input |
| `placeholder` | `string` | `undefined` | Placeholder text |
| ...rest | `InputHTMLAttributes` | - | All standard input attributes are supported |

### Type Definitions

```typescript
import { VariantProps } from "class-variance-authority";

export interface InputProps
  extends Omit<React.ComponentProps<"input">, "size">,
    VariantProps<typeof inputVariants> {}
```

**Note:** The native `size` attribute is omitted to avoid conflicts with the `inputSize` prop. Use `className` with width utilities if you need to control input width.

### Theme Integration

The Input component uses CSS variables from the TermCN theme system:

- `--background` - Input background color
- `--foreground` - Input text color
- `--muted-foreground` - Placeholder text color
- `--border` - Border color (bordered variant)
- `--primary` - Focus border color (bordered variant)
- `--primary` / `--primary-foreground` - Selection colors

### Extending Variants

To add custom variants, modify the `inputVariants` CVA definition:

```typescript
const inputVariants = cva(
  [
    "w-full bg-background text-foreground placeholder:text-muted-foreground",
    "border-0 outline-none",
    "font-mono transition-colors",
    // ... base styles
  ],
  {
    variants: {
      variant: {
        // ... existing variants
        underline: "border-b border-border focus:border-primary rounded-none",
      },
      inputSize: {
        // ... existing sizes
      },
    },
  }
);
```

## Accessibility

### Keyboard Navigation

- **Tab**: Focus the input
- **Shift + Tab**: Focus previous element
- **Enter**: Submit form (when input is in a form)

### Labels and ARIA

Always associate inputs with labels for accessibility:

```tsx
{/* Using htmlFor */}
<label htmlFor="email">Email</label>
<Input id="email" type="email" placeholder="Enter email" />

{/* Using aria-label */}
<Input aria-label="Search" placeholder="Search..." />

{/* Using aria-describedby for help text */}
<Input
  id="username"
  aria-describedby="username-help"
  placeholder="Username"
/>
<p id="username-help" className="text-xs text-muted-foreground">
  Must be 3-20 characters
</p>
```

### Error States

```tsx
{/* Invalid input */}
<Input
  aria-invalid="true"
  aria-describedby="email-error"
  className="border-destructive"
/>
<p id="email-error" className="text-xs text-destructive">
  Please enter a valid email address
</p>
```

### Screen Reader Support

Ensure meaningful labels and descriptions are provided:

```tsx
{/* Good */}
<label htmlFor="search">Search products</label>
<Input id="search" placeholder="Type to search..." />

{/* Better - with description */}
<Input
  id="search"
  aria-label="Search products"
  aria-describedby="search-hint"
  placeholder="Type to search..."
/>
<p id="search-hint" className="sr-only">
  Search through available products by name or category
</p>
```

## Best Practices

### When to Use Input

✅ **Good Use Cases:**
- Single-line text entry (names, emails, passwords)
- Search fields
- Form fields requiring short text
- Inline editing
- Command-line style interfaces
- File uploads

❌ **Avoid Using Input For:**
- Multi-line text (use Textarea instead)
- Rich text editing (use a rich text editor)
- Selecting from predefined options (use Select)
- Boolean choices (use Checkbox or Switch)
- Date/time picking (use dedicated pickers)

### Design Guidelines

1. **Use appropriate sizes**: Match input size to form context and importance
2. **Choose the right variant**: Use `bordered` when inputs need clear visual boundaries
3. **Provide placeholders wisely**: Use placeholders for hints, not labels
4. **Use proper input types**: Leverage native types (email, password, number) for mobile keyboards and validation
5. **Consider width**: Set explicit widths to prevent layout shifts
6. **Group related inputs**: Use consistent spacing and alignment

## Troubleshooting

### Input not showing border

Ensure you're using the `bordered` variant:

```tsx
{/* No border by default */}
<Input placeholder="No border" />

{/* Use bordered variant */}
<Input variant="bordered" placeholder="With border" />
```

### Size attribute conflict

The native `size` attribute is omitted to avoid conflicts. Use `inputSize` instead:

```tsx
{/* Wrong - size is omitted */}
<Input size={20} />

{/* Correct - use inputSize for component sizing */}
<Input inputSize="lg" />

{/* For width control, use className */}
<Input className="w-64" />
```

### Placeholder text color not showing

Verify your CSS variables are properly defined:

```css
:root {
  --muted-foreground: 240 5% 64.9%;
  /* ... other variables */
}
```

### Focus border not visible

Check if the bordered variant is applied and focus styles aren't being overridden:

```tsx
<Input variant="bordered" placeholder="Should show focus border" />
```
