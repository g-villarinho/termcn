# Button

Trigger actions and events with terminal-inspired button components featuring retro aesthetics and tactile interactions.

## Overview

The Button component is a fundamental interactive element designed to trigger actions, submit forms, and navigate through your application. Built with a distinctive terminal aesthetic, it features bold borders, 3D shadow effects, and tactile press interactions that evoke the feel of physical hardware buttons from retro computing interfaces.

## Features

- **9 Semantic Variants**: Default, Destructive, Outline, Secondary, Ghost, Link, Success, Warning, and Info
- **3D Terminal Aesthetics**: Bold borders with shadow effects that create depth and dimension
- **Tactile Interactions**: Physical button press effect with smooth transitions and shadow animations
- **Flexible Sizing**: Four size options (sm, default, lg, icon) for different use cases
- **Icon Support**: Seamless integration with SVG icons and custom content
- **Composition Pattern**: Support for asChild prop using Radix UI Slot for maximum flexibility
- **Fully Accessible**: Proper ARIA attributes, keyboard navigation, and focus states
- **TypeScript Support**: Fully typed with comprehensive prop definitions

## Installation

```bash

```

This will install the Button component and its dependencies into your project.

## API Reference

### Button Props

The Button component extends `React.ButtonHTMLAttributes<HTMLButtonElement>` and accepts the following props:

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `variant` | `"default" \| "destructive" \| "outline" \| "secondary" \| "ghost" \| "link" \| "success" \| "warning" \| "info"` | `"default"` | The visual style variant |
| `size` | `"default" \| "sm" \| "lg" \| "icon"` | `"default"` | The size of the button |
| `asChild` | `boolean` | `false` | Render as child element using Slot |
| `className` | `string` | `undefined` | Additional CSS classes to apply |
| `disabled` | `boolean` | `false` | Disable the button |
| ...rest | `ButtonHTMLAttributes` | - | All standard button attributes are supported |

### Type Definitions

```typescript
import { VariantProps } from "class-variance-authority";

export interface ButtonProps
  extends React.ButtonHTMLAttributes<HTMLButtonElement>,
    VariantProps<typeof buttonVariants> {
  asChild?: boolean;
}
```

## Best Practices

### When to Use Buttons

✅ **Good Use Cases:**
- Submitting forms
- Triggering actions (save, delete, etc.)
- Opening dialogs or modals
- Confirming or canceling operations
- Primary and secondary CTAs

❌ **Avoid Using Buttons For:**
- Navigation (use Link variant or anchor)
- Passive information display
- Non-interactive decorations
- When a link would be more semantic

### Design Guidelines

1. **Use clear, action-oriented labels**: "Save Changes" instead of "OK"
2. **Maintain visual hierarchy**: Primary actions use default variant, secondary actions use outline or secondary
3. **Be consistent**: Use the same variants for similar actions across your app
4. **Consider context**: Destructive actions should use the destructive variant
5. **Provide feedback**: Use loading states and disabled states appropriately
6. **Size appropriately**: Match button size to its importance and available space

## Design Details

### 3D Shadow Effect Breakdown

The terminal aesthetic is achieved through a combination of bold borders and animated shadows:

**Default State:**
- 2px solid border
- 0.25rem offset shadow (4px right, 4px down)

**Hover State:**
- Button moves 2px right and down
- Shadow reduces to 0.125rem offset (2px right, 2px down)

**Active/Pressed State:**
- Button moves 4px right and down
- Shadow disappears completely
- Creates illusion of button being pressed into the surface

### Implementation Details

The 3D effect is created using:

```tsx
// Default state
className="border-2 border-primary shadow-[0.25rem_0.25rem_0_0_hsl(var(--primary))]"

// Hover state
className="hover:translate-x-[0.125rem] hover:translate-y-[0.125rem] hover:shadow-[0.125rem_0.125rem_0_0_hsl(var(--primary))]"

// Active state
className="active:translate-x-[0.25rem] active:translate-y-[0.25rem] active:shadow-none"
```

All states use `transition-all` for smooth animations between states.

## Troubleshooting

### Shadow not displaying correctly

Ensure your Tailwind CSS configuration supports arbitrary values:

```js
// tailwind.config.js
module.exports = {
  theme: {
    extend: {
      // Arbitrary values are supported by default
    },
  },
}
```

### Button not responding to clicks

Check if the button is disabled or if there's a z-index issue with overlapping elements:

```tsx
{/* Make sure disabled is intentional */}
<Button disabled={isProcessing}>Submit</Button>

{/* Ensure proper stacking context */}
<Button className="relative z-10">Clickable</Button>
```

### Theme colors not applying

Verify your CSS variables are properly defined in your global styles:

```css
:root {
  --primary: 220 100% 50%;
  --primary-foreground: 0 0% 100%;
  /* ... other variables */
}
```

## Migration Guide

### From shadcn/ui Button

The TermCN Button is highly compatible with shadcn/ui with enhanced 3D effects:

```diff
  import { Button } from "@/components/ui/button";

  // Basic usage remains the same
  <Button>Click me</Button>

  // Variants are similar
  <Button variant="default">Default</Button>
  <Button variant="destructive">Destructive</Button>
  <Button variant="outline">Outline</Button>
  <Button variant="secondary">Secondary</Button>
  <Button variant="ghost">Ghost</Button>
  <Button variant="link">Link</Button>

  // New variants in TermCN
+ <Button variant="success">Success</Button>
+ <Button variant="warning">Warning</Button>
+ <Button variant="info">Info</Button>

  // 3D effect is automatic - no changes needed
  // The terminal aesthetic applies to all variants
```
