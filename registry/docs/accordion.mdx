# Accordion

Expandable content sections with terminal-inspired tree navigation and collapsible panels.

## Overview

The Accordion component is a vertically stacked set of interactive headings that reveal or hide associated content sections. Built with a distinctive terminal aesthetic, it features tree-style navigation indicators (▸/▾) in ANSI blue that evoke directory expansion in command-line file browsers and text-based user interfaces.

## Features

- **Tree-Style Navigation**: ANSI blue triangle indicators (▸/▾) mimicking terminal directory trees
- **Single or Multiple Expansion**: Control whether one or multiple items can be open simultaneously
- **Smooth Transitions**: Content reveals with clean state-based visibility
- **Terminal Aesthetics**: Monospace typography and border styling consistent with CLI interfaces
- **Fully Accessible**: Built on Radix UI primitives with complete keyboard navigation and ARIA support
- **Composition Pattern**: Flexible compound component API for maximum customization
- **TypeScript Support**: Fully typed with comprehensive prop definitions
- **Collapsible Mode**: Optional ability to close all items when clicking an open item

## Installation

```bash
npx termcn add accordion
```

This will install the Accordion component and its dependencies into your project.

## API Reference

### Accordion Props

The Accordion component wraps `@radix-ui/react-accordion` Root and accepts the following props:

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `type` | `"single" \| "multiple"` | Required | Whether one or multiple items can be open |
| `collapsible` | `boolean` | `false` | When `type="single"`, allows closing all items |
| `defaultValue` | `string \| string[]` | `undefined` | Default open item(s) |
| `value` | `string \| string[]` | `undefined` | Controlled open item(s) |
| `onValueChange` | `(value: string \| string[]) => void` | `undefined` | Called when open items change |
| `disabled` | `boolean` | `false` | Disable all items |
| `className` | `string` | `undefined` | Additional CSS classes |

### AccordionItem Props

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `value` | `string` | Required | Unique identifier for the item |
| `disabled` | `boolean` | `false` | Disable this specific item |
| `className` | `string` | `undefined` | Additional CSS classes |

### AccordionTrigger Props

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `className` | `string` | `undefined` | Additional CSS classes |
| `children` | `React.ReactNode` | Required | The trigger content |

### AccordionContent Props

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `className` | `string` | `undefined` | Additional CSS classes |
| `children` | `React.ReactNode` | Required | The expandable content |

### Type Definitions

```typescript
import * as AccordionPrimitive from "@radix-ui/react-accordion";

// Accordion root props
type AccordionProps = React.ComponentProps<typeof AccordionPrimitive.Root>;

// AccordionItem props
type AccordionItemProps = React.ComponentProps<typeof AccordionPrimitive.Item>;

// AccordionTrigger props
type AccordionTriggerProps = React.ComponentProps<typeof AccordionPrimitive.Trigger>;

// AccordionContent props
type AccordionContentProps = React.ComponentProps<typeof AccordionPrimitive.Content>;
```

To use different expansion indicators, override the trigger styles:


```typescript

        className

      {...props}

      {/* ... */}
```

## Accessibility

### Keyboard Navigation

- **Tab**: Move focus between accordion triggers
- **Enter/Space**: Toggle the focused accordion item
- **Arrow Down**: Move focus to the next trigger
- **Arrow Up**: Move focus to the previous trigger
- **Home**: Move focus to the first trigger
- **End**: Move focus to the last trigger

## Best Practices

### When to Use Accordions

✅ **Good Use Cases:**
- FAQ sections with question/answer pairs
- Settings panels with categorized options
- Documentation with expandable sections
- File trees and nested navigation
- Progressive disclosure of complex content
- Mobile-friendly content organization

❌ **Avoid Using Accordions For:**
- Critical information that users must see (use alerts)
- Primary navigation (use proper nav components)
- Content that users need to compare side-by-side
- Very short content (just show it directly)
- Single-item collapsibles (use a disclosure component)

### Design Guidelines

1. **Use descriptive triggers**: Labels should clearly indicate what content will be revealed
2. **Keep content focused**: Each section should cover one topic or category
3. **Consider default state**: Open important sections by default if users need them immediately
4. **Maintain consistency**: Use consistent trigger formatting and content structure
5. **Group related items**: Organize accordion items logically for easy scanning
6. **Limit nesting**: Avoid deeply nested accordions; use other patterns for complex hierarchies

## Design Details

### Terminal Tree Indicators

The tree-style indicators are implemented using ANSI blue colored triangles:

**Collapsed State:**
- Right-pointing triangle (▸) indicates expandable content
- Displayed in `text-ansi-blue` color

**Expanded State:**
- Down-pointing triangle (▾) indicates collapsible content
- Smooth state transition using `data-[state=open/closed]` selectors

### Implementation Details

```tsx
// Trigger indicator implementation
<span className="text-ansi-blue shrink-0 group-data-[state=open]:hidden">
  ▸
</span>
<span className="text-ansi-blue shrink-0 hidden group-data-[state=open]:inline">
  ▾
</span>
```

### Border Styling

Items are separated by bottom borders with the last item having no border:

```tsx
className="border-b border-border last:border-b-0"
```

## Performance

The Accordion component is lightweight and performant:

- **Lazy rendering**: Content is hidden via CSS, not unmounted
- **Minimal JavaScript**: Built on Radix UI primitives with optimized state management
- **Small bundle size**: ~3KB including Radix dependency
- **Server-side rendering**: Fully compatible with SSR frameworks
- **No layout shift**: Content containers maintain size during transitions

## Troubleshooting

### Content not expanding

Ensure each `AccordionItem` has a unique `value` prop:

```tsx
{/* Each item needs a unique value */}
<AccordionItem value="unique-id-1">...</AccordionItem>
<AccordionItem value="unique-id-2">...</AccordionItem>
```

### Collapsible not working

The `collapsible` prop only works with `type="single"`:

```tsx
{/* Correct - collapsible with single type */}
<Accordion type="single" collapsible>

{/* Incorrect - collapsible ignored with multiple type */}
<Accordion type="multiple" collapsible>
```

### Indicators not showing

Verify the ANSI color CSS variables are defined in your theme:

```css
:root {
  --ansi-blue: 210 100% 60%;
}
```

### Focus styles not visible

Ensure your global styles include focus-visible utilities:

```tsx
<AccordionTrigger className="focus-visible:ring-2 focus-visible:ring-ring">
  Trigger
</AccordionTrigger>
```

## Migration Guide

### From shadcn/ui Accordion

The TermCN Accordion is compatible with shadcn/ui with terminal styling:

```diff
  import {
    Accordion,
    AccordionItem,
    AccordionTrigger,
    AccordionContent,
  } from "@/components/ui/accordion";

  // Basic usage remains the same
  <Accordion type="single" collapsible>
    <AccordionItem value="item-1">
      <AccordionTrigger>Title</AccordionTrigger>
      <AccordionContent>Content</AccordionContent>
    </AccordionItem>
  </Accordion>

- // shadcn/ui uses ChevronDown icon with rotation animation
+ // TermCN uses ANSI blue triangle indicators (▸/▾)
+ // Terminal-inspired styling is automatic
```
