# Switch

Toggle between on and off states with terminal-inspired switch components featuring retro slider aesthetics.

## Overview

The Switch component is a binary input control designed to toggle between two mutually exclusive states: on and off. Built with a distinctive terminal aesthetic in mind, it features a clean slider design with customizable track bars and smooth thumb transitions. The component evokes the feel of physical toggle switches from retro computing interfaces and hardware control panels.

## Features

- **2 Size Variants**: Default (4ch width) and Small (2ch width) for different layout needs
- **3 Bar Styles**: Default full-height, Thin (0.5lh), and Line (2px) track options
- **Terminal-Inspired Design**: Monospace-friendly dimensions using `ch` and `lh` units
- **Smooth Transitions**: Animated thumb movement with polished state changes
- **Visual State Feedback**: Clear distinction between checked and unchecked states
- **Fully Accessible**: Built on Radix UI primitives with proper ARIA attributes and keyboard navigation
- **Composition Ready**: Integrates seamlessly with form labels and descriptions
- **TypeScript Support**: Fully typed with comprehensive prop definitions

## API Reference

### Switch Props

The Switch component extends `React.ComponentPropsWithoutRef<typeof SwitchPrimitive.Root>` and accepts the following props:

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `size` | `"default" \| "sm"` | `"default"` | The size of the switch |
| `bar` | `"default" \| "thin" \| "line"` | `"default"` | The track bar style |
| `checked` | `boolean` | `undefined` | Controlled checked state |
| `defaultChecked` | `boolean` | `false` | Initial checked state (uncontrolled) |
| `onCheckedChange` | `(checked: boolean) => void` | `undefined` | Callback when checked state changes |
| `disabled` | `boolean` | `false` | Disable the switch |
| `required` | `boolean` | `false` | Mark as required for form validation |
| `name` | `string` | `undefined` | Name for form submission |
| `value` | `string` | `"on"` | Value for form submission |
| `className` | `string` | `undefined` | Additional CSS classes to apply |
| ...rest | `SwitchPrimitive.Root` attributes | - | All Radix Switch root attributes are supported |

### Type Definitions

```typescript
import * as SwitchPrimitive from "@radix-ui/react-switch";
import { VariantProps } from "class-variance-authority";

interface SwitchProps
  extends React.ComponentPropsWithoutRef<typeof SwitchPrimitive.Root>,
    VariantProps<typeof switchVariants> {}
```

### Extending Variants

To add custom variants, modify the `switchVariants` CVA definition:

```typescript
const switchVariants = cva(
  "peer group relative inline-flex shrink-0 cursor-pointer items-center outline-none transition-colors focus-visible:ring-2 focus-visible:ring-ring disabled:cursor-not-allowed disabled:opacity-50",
  {
    variants: {
      size: {
        default: "h-lh w-[4ch]",
        sm: "h-lh w-[2ch]",
        // Add custom size
        lg: "h-lh w-[6ch]",
      },
      bar: {
        default: "",
        thin: "[--bar-height:0.5lh]",
        line: "[--bar-height:2px]",
        // Add custom bar style
        dot: "[--bar-height:4px]",
      },
    },
  }
);
```

## Best Practices

### When to Use Switches

✅ **Good Use Cases:**
- Settings that take effect immediately
- Binary on/off toggles
- Feature flags and preferences
- Enabling/disabling functionality
- Status toggles (available/away, online/offline)

❌ **Avoid Using Switches For:**
- Form submissions that require a save button (use checkboxes instead)
- Multiple related options (use checkbox group)
- Mutually exclusive options with more than 2 choices (use radio buttons)
- Actions that need confirmation (use buttons with confirmation dialogs)

### Design Guidelines

1. **Use clear, descriptive labels**: Labels should describe what happens when the switch is on
2. **Immediate feedback**: Switches should apply changes immediately without requiring a save action
3. **Consistent positioning**: Place switches consistently (typically to the right of labels)
4. **Provide visual feedback**: Users should clearly see the current state
5. **Consider accessibility**: Always pair with labels for screen readers
6. **Use appropriate sizes**: Default for standalone, small for compact layouts

## Design Details

### Terminal-Inspired Dimensions

The Switch uses typography-relative units for seamless integration with monospace layouts:

**Default Size:**
- Container: `h-lh w-[4ch]` (line-height × 4 characters)
- Thumb: `h-lh w-[2ch]` (line-height × 2 characters)
- Translation: `translate-x-[2ch]` when checked

**Small Size:**
- Container: `h-lh w-[2ch]` (line-height × 2 characters)
- Thumb: `h-lh w-[1ch]` (line-height × 1 character)
- Translation: `translate-x-[1ch]` when checked

### Bar Style Implementation

Bar styles use CSS custom properties for flexible track heights:

```css
/* Default: full height */
--bar-height: 1lh;

/* Thin: half height */
--bar-height: 0.5lh;

/* Line: minimal */
--bar-height: 2px;
```

### State Transitions

The component uses smooth transitions for polished interactions:

- Thumb color: `transition-all` for color and position changes
- Thumb position: Translates horizontally based on checked state
- Focus ring: `focus-visible:ring-2` for keyboard focus indication

- **Toggle**: For button-style binary toggles

## Troubleshooting

### Switch not toggling

Ensure you're handling the controlled state correctly:

```tsx
{/* Uncontrolled - works automatically */}
<Switch />

{/* Controlled - requires state management */}
const [checked, setChecked] = useState(false);
<Switch checked={checked} onCheckedChange={setChecked} />
```

### Focus ring not visible

Check that your global styles include the ring color variable:

```css
:root {
  --ring: 220 100% 50%;
}
```

### Thumb not animating

Ensure `transition-all` is not being overridden by custom classes:

```tsx
{/* Avoid overriding transitions */}
<Switch className="transition-none" /> {/* This breaks animations */}
```

### Form submission not working

Make sure to provide `name` prop for form data:

```tsx
<Switch name="preference" value="enabled" />
```
