# Input Group

Combine inputs with addons, buttons, and text for enhanced terminal-style form fields.

## Overview

The Input Group component provides a composable way to combine input fields with additional elements like icons, text labels, buttons, and other addons. Built with terminal aesthetics in mind, it features monospace typography, clean borders, and seamless integration with the TermCN theme system. The component uses a composition pattern that allows flexible arrangement of elements while maintaining visual consistency.

## Features

- **3 Visual Variants**: Default (minimal), Bordered, and Field for different design contexts
- **3 Size Options**: Small, Default, and Large for flexible layouts
- **Composable Architecture**: Mix and match input, addons, buttons, and text
- **Terminal Typography**: JetBrains Mono font throughout all elements
- **Focus Ring Styling**: Clean focus states with primary color ring
- **Flexible Alignment**: Support for inline-start and inline-end addon positioning
- **Textarea Support**: Multiline input with automatic height adjustment
- **Fully Accessible**: Proper focus states and semantic HTML structure
- **TypeScript Support**: Fully typed with comprehensive prop definitions

## Installation

```bash
npx termcn add input-group
```

This will install the Input Group component and its dependencies into your project.

## Dependencies

- `class-variance-authority` - For type-safe variant management
- `@/lib/utils` - For className merging utilities

## API Reference

### InputGroup Props

The InputGroup component extends `React.ComponentProps<"div">` and accepts the following props:

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `variant` | `"default" \| "bordered" \| "field"` | `"default"` | The visual style variant |
| `size` | `"sm" \| "default" \| "lg"` | `"default"` | The size of the input group |
| `className` | `string` | `undefined` | Additional CSS classes to apply |
| ...rest | `HTMLDivElement` | - | All standard div attributes are supported |

### InputGroupInput Props

Extends all native `<input>` HTML attributes.

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `className` | `string` | `undefined` | Additional CSS classes |
| `placeholder` | `string` | `undefined` | Placeholder text |
| `disabled` | `boolean` | `false` | Disable the input |
| ...rest | `InputHTMLAttributes` | - | All standard input attributes |

### InputGroupTextarea Props

Extends all native `<textarea>` HTML attributes.

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `className` | `string` | `undefined` | Additional CSS classes |
| `placeholder` | `string` | `undefined` | Placeholder text |
| `disabled` | `boolean` | `false` | Disable the textarea |
| ...rest | `TextareaHTMLAttributes` | - | All standard textarea attributes |

### InputGroupAddon Props

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `align` | `"inline-start" \| "inline-end"` | `"inline-start"` | Position alignment (for data attribute) |
| `className` | `string` | `undefined` | Additional CSS classes |
| ...rest | `HTMLDivElement` | - | All standard div attributes |

### InputGroupButton Props

Extends all native `<button>` HTML attributes.

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `type` | `"button" \| "submit" \| "reset"` | `"button"` | Button type |
| `disabled` | `boolean` | `false` | Disable the button |
| `className` | `string` | `undefined` | Additional CSS classes |
| ...rest | `ButtonHTMLAttributes` | - | All standard button attributes |

### InputGroupText Props

Extends all native `<span>` HTML attributes.

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `className` | `string` | `undefined` | Additional CSS classes |
| ...rest | `HTMLSpanElement` | - | All standard span attributes |

### Theme Integration

The Input Group component uses CSS variables from the TermCN theme system:

- `--background` - Input group background color
- `--background1` - Field variant background
- `--background2` - Button hover background
- `--foreground` - Input text color
- `--muted-foreground` - Addon and placeholder text color
- `--border` - Border color
- `--primary` - Focus ring color

### Extending Variants

To add custom variants, modify the `inputGroupVariants` CVA definition:

```typescript
const inputGroupVariants = cva(
  [
    "flex w-full items-center font-mono text-sm",
    "bg-background text-foreground",
    // ... base styles
  ],
  {
    variants: {
      variant: {
        // ... existing variants
        terminal: "border-2 border-ansi-green bg-background1",
        error: "border-2 border-destructive",
      },
    },
  }
);
```

## Accessibility

### Keyboard Navigation

- **Tab**: Focus the input/button within the group
- **Shift + Tab**: Focus previous element
- **Enter**: Submit form or trigger button action

### Labels and ARIA

Always associate input groups with labels for accessibility:

```tsx
{/* Using htmlFor */}
<label htmlFor="email">Email</label>
<InputGroup variant="bordered">
  <InputGroupAddon>
    <MailIcon className="size-4" />
  </InputGroupAddon>
  <InputGroupInput id="email" type="email" placeholder="Enter email" />
</InputGroup>

{/* Using aria-label */}
<InputGroup variant="bordered">
  <InputGroupInput aria-label="Search" placeholder="Search..." />
</InputGroup>

{/* Using aria-describedby */}
<InputGroup variant="bordered">
  <InputGroupInput
    id="api-key"
    aria-describedby="api-key-help"
    placeholder="sk-..."
  />
</InputGroup>
<p id="api-key-help" className="text-xs text-muted-foreground">
  Your API key will be encrypted
</p>
```

### Focus Management

The InputGroup uses `has-*` selectors to show focus state on the container when the input is focused:

```tsx
className="has-[[data-slot=input-group-input]:focus]:ring-1 has-[[data-slot=input-group-input]:focus]:ring-primary"
```

## Best Practices

### When to Use InputGroup

✅ **Good Use Cases:**
- Inputs that need visual context (icons, prefixes, suffixes)
- Search fields with action buttons
- Currency or unit inputs
- URL inputs with protocol prefix
- Command-line style inputs
- Inputs with copy/paste buttons

❌ **Avoid Using InputGroup For:**
- Simple inputs without addons (use Input directly)
- Complex form layouts (use form components)
- Inputs that don't need visual context

### Design Guidelines

1. **Keep addons minimal**: Use icons or short text, not lengthy labels
2. **Use appropriate sizes**: Match size to surrounding UI context
3. **Choose the right variant**: Use `bordered` for forms, `field` for darker contexts
4. **Consider mobile**: Ensure touch targets are large enough (minimum 44px)
5. **Maintain consistency**: Use the same variant throughout a form
6. **Order logically**: Place addons where users expect them (currency symbol before, units after)

## Troubleshooting

### Focus ring not showing

Ensure the InputGroupInput is a direct child of InputGroup:

```tsx
{/* Correct */}
<InputGroup variant="bordered">
  <InputGroupInput placeholder="Works" />
</InputGroup>

{/* Incorrect - wrapper div breaks focus detection */}
<InputGroup variant="bordered">
  <div>
    <InputGroupInput placeholder="No focus ring" />
  </div>
</InputGroup>
```

### Addon not aligned properly

Use `self-start` for vertical alignment with textarea:

```tsx
<InputGroup variant="bordered">
  <InputGroupAddon className="self-start pt-2">
    <Icon />
  </InputGroupAddon>
  <InputGroupTextarea placeholder="Multiline..." />
</InputGroup>
```

### Button hover not visible

Ensure the button is receiving the default styles:

```tsx
{/* If custom styling overrides hover, add it back */}
<InputGroupButton className="hover:bg-background2 hover:text-foreground">
  <Icon />
</InputGroupButton>
```
