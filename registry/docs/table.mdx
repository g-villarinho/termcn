# Table

Display structured data with terminal-inspired table components featuring monospace typography and grid-like aesthetics.

## Overview

The Table component is a comprehensive data display system designed to present structured information in a clean, organized format. Built with terminal aesthetics in mind, it features monospace typography, clear grid lines, and subtle hover interactions that evoke the feel of data tables in terminal applications and text-based interfaces.

## Features

- **Complete Table System**: 8 composable components (Table, TableHeader, TableBody, TableFooter, TableHead, TableRow, TableCell, TableCaption)
- **Terminal-Inspired Design**: Monospace font, bordered cells, and distinct visual hierarchy
- **Grid Aesthetics**: Clear cell separators with vertical and horizontal borders
- **Interactive Rows**: Hover states and selection indicators for data navigation
- **Responsive Container**: Horizontal scrolling for wide tables on smaller screens
- **Semantic Structure**: Proper HTML table elements for accessibility and SEO
- **Theme Integration**: Seamless integration with TermCN color system using ANSI-inspired colors
- **TypeScript Support**: Fully typed with comprehensive prop definitions

## Installation

```bash
npx termcn add table
```

This will install the Table component and its dependencies into your project.

### Theme Integration

The Table component uses CSS variables from the TermCN theme system:

- `--border` - Cell border color
- `--background1` - Table container background
- `--background2` - Header and footer background, hover state
- `--background3` - Selected row background
- `--foreground` - Cell text color
- `--foreground2` - Caption text color
- `--ansi-blue` - Header text color
- `--ansi-cyan` - Selected row text color

Create reusable column configurations:


The Table component uses proper semantic HTML elements:

- `<table>` - Main table container
- `<thead>` - Table header section
- `<tbody>` - Table body section
- `<tfoot>` - Table footer section
- `<tr>` - Table rows

### Keyboard Navigation

Tables support standard keyboard navigation:

- **Tab**: Move between interactive elements within cells
- **Arrow keys**: Navigate between cells (with proper ARIA implementation)
- **Enter/Space**: Activate interactive elements


## Best Practices

### When to Use Tables

✅ **Good Use Cases:**
- Displaying structured, tabular data
- Comparing multiple items across the same attributes
- Showing lists with multiple properties per item
- Financial data, statistics, and metrics
- Log entries and historical records

❌ **Avoid Using Tables For:**
- Layout purposes (use CSS Grid or Flexbox instead)
- Single-column lists (use List components)
- Complex nested data (consider tree views or cards)
- Mobile-first designs where horizontal scrolling is problematic

### Design Guidelines

1. **Keep headers descriptive**: Use clear, concise column headers
2. **Align data appropriately**: Numbers right-aligned, text left-aligned
3. **Use consistent formatting**: Same number of decimals, date formats, etc.
4. **Limit column count**: Aim for 3-7 columns on desktop
5. **Consider mobile**: Wide tables should scroll horizontally
6. **Highlight important data**: Use selection states and color coding sparingly
7. **Add context with captions**: Help users understand the table's purpose

## Design Details

### Visual Structure

The Table component creates a distinctive terminal aesthetic through:

**Container:**
- Outer border with `border-border` color
- `background1` background color
- Monospace font family
- Horizontal scroll for overflow content

**Headers:**
- `background2` background for visual separation
- Bold text in `ansi-blue` color
- Vertical separators between columns
- Fixed height of 32px (h-8)

**Cells:**
- Vertical cell separators (except last column)
- Horizontal row separators
- `whitespace-nowrap` to prevent text wrapping
- Consistent padding (px-3 py-2)

**Interactions:**
- Hover state changes row background to `background2`
- Selected state uses `background3` with `ansi-cyan` text

### Implementation Details


```tsx
      </TableHeader>
      <TableBody>
        {sortedData.map((item) => (
          <TableRow key={item.id}>
            <TableCell>{item.name}</TableCell>
            <TableCell>{item.date}</TableCell>
          </TableRow>
        ))}
      </TableBody>
    </Table>
  );
}
```

## Performance

The Table component is lightweight and performant:

- Pure CSS styling with no JavaScript runtime
- Semantic HTML for optimal rendering
- Small bundle size impact (~1.5KB)
- Server-side rendering compatible
- Virtualization-ready for large datasets (pair with react-virtual)

### Large Dataset Optimization

For tables with hundreds or thousands of rows, consider:

```tsx
import { useVirtualizer } from "@tanstack/react-virtual";

function VirtualizedTable({ data }) {
  const parentRef = useRef(null);
  const virtualizer = useVirtualizer({
    count: data.length,
    getScrollElement: () => parentRef.current,
    estimateSize: () => 40,
  });

  return (
    <div ref={parentRef} className="h-[400px] overflow-auto">
      <Table>
        <TableHeader>...</TableHeader>
        <TableBody>
          {virtualizer.getVirtualItems().map((virtualRow) => (
            <TableRow key={virtualRow.key}>
              <TableCell>{data[virtualRow.index].name}</TableCell>
            </TableRow>
          ))}
        </TableBody>
      </Table>
    </div>
  );
}
```

## Troubleshooting

### Table not scrolling horizontally

Ensure the table container has proper overflow settings:

```tsx
{/* The Table component includes horizontal scroll by default */}
<Table className="min-w-[800px]">
  {/* Wide content */}
</Table>
```

### Borders not displaying correctly

Verify your Tailwind CSS configuration includes border utilities and the theme variables are defined:

```css
:root {
  --border: 240 5% 26%;
  /* ... other variables */
}
```

### Header not sticky

Add sticky positioning to the header:

```tsx
<TableHeader className="sticky top-0 z-10 bg-background2">
  ...
</TableHeader>
```

### Selected state not applying

Ensure you're using the correct data attribute format:

```tsx
{/* Correct */}
<TableRow data-state="selected">

{/* Incorrect */}
<TableRow selected>
<TableRow data-selected>
```
