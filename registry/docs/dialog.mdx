# Dialog

Display modal content and interactive overlays with terminal-inspired dialog components featuring 3D shadow effects and position variants.

## Overview

The Dialog component is a modal overlay element designed to capture user attention and present focused content, forms, or confirmations. Built on Radix UI's accessible dialog primitive, it features a distinctive terminal aesthetic with bold borders, 3D shadow effects, and a frosted glass overlay that evokes the feel of pop-up windows from retro computing interfaces.

## Features

- **9 Position Variants**: Center, top-left, top-center, top-right, center-left, center-right, bottom-left, bottom-center, and bottom-right
- **5 Size Options**: Small, default, large, extra-large, and full-screen for different content needs
- **2 Elevation Styles**: Flat (default) or raised with 3D shadow effect
- **3D Terminal Aesthetics**: Bold borders with optional offset shadow effects creating depth and dimension
- **Frosted Glass Overlay**: Semi-transparent backdrop with blur effect for modern depth
- **Smooth Animations**: Fade and zoom transitions for open/close states
- **Flexible Composition**: Modular sub-components for header, footer, title, and description
- **Accessible Close Button**: Optional X button with proper focus states and screen reader support
- **Fully Accessible**: Built on Radix UI with proper ARIA attributes, focus trapping, and keyboard navigation
- **TypeScript Support**: Fully typed with comprehensive prop definitions

## Installation

```bash
npx termcn add dialog
```

This will install the Dialog component and its dependencies into your project.

## API Reference

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `open` | `boolean` | `undefined` | Controlled open state |

### Extending Variants

To add custom position, size, or elevation variants, modify the `dialogContentVariants` CVA definition:

```typescript
const dialogContentVariants = cva(
  // Base styles
  [...],
  {
    variants: {
      position: {
        // ... existing positions
        custom: "top-20 left-20",
      },
      size: {
        // ... existing sizes
        custom: "w-[500px] max-w-none p-8",
      },
      elevation: {
        // ... existing elevations
        floating: "shadow-lg shadow-primary/20",
      },
    },
  }
);
```

## Accessibility

### Keyboard Navigation

- **Tab**: Move focus between focusable elements within the dialog
- **Shift + Tab**: Move focus backwards
- **Escape**: Close the dialog
- **Enter**: Activate focused button

### Focus Management

The dialog automatically:
- Traps focus within the dialog when open
- Returns focus to the trigger element when closed
- Focuses the first focusable element on open

### ARIA Attributes


- `DialogTitle` is announced as the dialog's accessible name
- `DialogDescription` is announced as the dialog's accessible description
- Close button includes `sr-only` text for screen readers

## Best Practices

### When to Use Dialogs

**Good Use Cases:**
- Confirmation prompts for destructive actions
- Form inputs that require focused attention
- Important alerts or warnings
- Multi-step wizards or flows
- Media viewers or lightboxes
- Settings panels

**Avoid Using Dialogs For:**
- Simple notifications (use toasts instead)
- Non-critical information (use inline content)
- Frequent actions that interrupt workflow
- Content that should be bookmarkable/shareable
- Mobile navigation (use sheets/drawers instead)

### Design Guidelines

1. **Keep dialogs focused**: One primary action per dialog
2. **Provide clear actions**: Use descriptive button labels ("Save Changes" not "OK")
3. **Use appropriate sizes**: Match dialog size to content complexity
4. **Consider position**: Use corner positions for non-blocking alerts
5. **Include escape routes**: Always provide a way to dismiss the dialog
6. **Maintain hierarchy**: Primary action should be visually prominent

## Design Details

### 3D Shadow Effect Breakdown

The terminal aesthetic is achieved through a combination of bold borders and optional offset shadows:

**Default State (flat):**
- 2px solid border
- No shadow
- Sharp corners (0px border-radius)
- Monospace font throughout

**Raised State:**
- 2px solid border
- 0.5rem offset shadow (8px right, 8px down) using background2 color
- Sharp corners (0px border-radius)
- Monospace font throughout

**Visual Structure:**
```css
/* Flat (default) */
border: 2px solid var(--border);
background: var(--background);

/* Raised */
border: 2px solid var(--border);
background: var(--background);
box-shadow: 0.5rem 0.5rem 0 0 var(--background2);
```

### Overlay Design

The overlay uses a frosted glass effect:
- Background: `crust` color at 80% opacity
- Backdrop blur: `backdrop-blur-sm`
- Smooth fade animation on open/close

### Animation Details

- **Modal**: Alternative naming for dialog pattern

## Troubleshooting

### Dialog not opening

Ensure the trigger has proper event handling:

```tsx
{/* Make sure to use asChild with a valid button element */}
<DialogTrigger asChild>
  <Button>Open</Button>
</DialogTrigger>
```

### Focus not being trapped

Check if there are focusable elements outside the dialog that might interfere:

```tsx
{/* Ensure modal prop is true (default) */}
<Dialog modal={true}>
  {/* ... */}
</Dialog>
```

### Animation not working

Verify Tailwind CSS animate utilities are configured:

```js
// tailwind.config.js
module.exports = {
  theme: {
    extend: {
      animation: {
        "fade-in": "fade-in 0.2s ease-out",
        "zoom-in": "zoom-in 0.2s ease-out",
      },
    },
  },
}
```

### Z-index conflicts

The dialog uses `z-50` by default. Adjust if needed:

```tsx
<DialogContent className="z-[100]">
  Higher z-index content
</DialogContent>
```
