# Sheet

Display slide-out panels from screen edges with terminal-inspired sheet components featuring bold borders and grayscale overlays.

## Overview

The Sheet component is a slide-out panel element designed to display supplementary content, navigation menus, or forms without fully replacing the main content. Built on Radix UI's accessible dialog primitive, it features a distinctive terminal aesthetic with bold borders, monospace typography, and a unique grayscale backdrop overlay that evokes the feel of auxiliary terminal windows from retro computing interfaces.

## Features

- **4 Side Variants**: Slide from right, left, top, or bottom edges of the screen
- **Terminal Aesthetics**: Bold 2px borders, monospace font throughout, sharp corners
- **Grayscale Overlay**: Unique backdrop-grayscale effect for a distinctive terminal look
- **Modular Composition**: SheetHeader, SheetBody, SheetFooter for organized layouts
- **Smooth Animations**: Fade transitions for open/close states
- **Optional Close Button**: Built-in X button with showCloseButton prop
- **Fully Accessible**: Built on Radix UI with proper ARIA attributes, focus trapping, and keyboard navigation
- **TypeScript Support**: Fully typed with comprehensive prop definitions

## Installation

```bash
npx termcn add sheet
```

This will install the Sheet component and its dependencies into your project.

## Accessibility

### Keyboard Navigation

- **Tab**: Move focus between focusable elements within the sheet
- **Shift + Tab**: Move focus backwards
- **Escape**: Close the sheet
- **Enter**: Activate focused button

### Focus Management

The sheet automatically:
- Traps focus within the sheet when open
- Returns focus to the trigger element when closed
- Focuses the first focusable element on open

## Best Practices

### When to Use Sheets

**Good Use Cases:**
- Mobile navigation menus
- Filter and settings panels
- Shopping carts or item lists
- Quick actions and contextual menus
- Preview panels for list items
- Form wizards or multi-step processes

**Avoid Using Sheets For:**
- Critical confirmations (use Dialog instead)
- Primary content that should be always visible
- Simple tooltips or popovers
- Content that needs to be bookmarkable
- Full-page experiences (use routes instead)

### Design Guidelines

1. **Choose the right side**: Use left for navigation, right for details, bottom for mobile actions
2. **Keep content focused**: One primary purpose per sheet
3. **Use proper hierarchy**: Header for context, body for content, footer for actions
4. **Consider mobile**: Bottom sheets work best on touch devices
5. **Provide escape routes**: Always offer a way to close the sheet
6. **Maintain scroll**: Use SheetBody for scrollable content

## Design Details

### Terminal Aesthetic Breakdown

The sheet achieves its terminal look through careful styling:

**Content Panel:**
- 2px solid border for bold, defined edges
- Sharp corners (0px border-radius) for authentic terminal feel
- Monospace font (`font-mono`) throughout
- Background uses theme's base color

**Overlay:**
- Semi-transparent black (`bg-black/50`)
- Unique `backdrop-grayscale` effect creating a desaturated background
- Creates focus on the sheet content

**Close Button:**
- 6x6 icon container with border
- Hover state with muted background
- Transition for smooth interactions

**Visual Structure:**
```css
/* Sheet Content */
border: 2px solid var(--border);
background: var(--background);
font-family: var(--font-mono);

/* Overlay */
background: rgba(0, 0, 0, 0.5);
backdrop-filter: grayscale(1);

/* Header/Footer */
background: var(--background1);
```

## Troubleshooting

### Sheet not sliding correctly

Ensure you're using the correct `side` prop:

```tsx
{/* Valid side values */}
<SheetContent side="right" /> {/* default */}
<SheetContent side="left" />
<SheetContent side="top" />
<SheetContent side="bottom" />
```

### Content overflowing

Use SheetBody for scrollable content:

```tsx
<SheetContent>
  <SheetHeader>...</SheetHeader>
  <SheetBody> {/* Adds overflow-auto */}
    {/* Long content */}
  </SheetBody>
  <SheetFooter>...</SheetFooter>
</SheetContent>
```

### Focus not being trapped

Check if there are focusable elements outside the sheet that might interfere:

```tsx
{/* Ensure modal prop is true (default) */}
<Sheet modal={true}>
  {/* ... */}
</Sheet>
```

### Z-index conflicts

The sheet uses `z-50` by default. Adjust if needed:

```tsx
<SheetContent className="z-[100]">
  Higher z-index content
</SheetContent>
```
